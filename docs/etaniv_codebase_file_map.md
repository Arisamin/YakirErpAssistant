## 1. סקירה כללית ותקציר ארכיטקטוני

פרויקט `From Yakir/etaniv-app_21/` מהווה מערכת מונורפו (Monorepo) מלאה ומאובטחת לניהול פיננסי-פרויקטלי עבור חברת **אתניב ב.י בע"מ** (טכנולוגיות מים וסביבה).  
המערכת נבנתה בארכיטקטורת שני ראשים:
- **צד שרת (`server/`):** מבוסס Node.js (גרסה 20/22), TypeScript, Express.js, Prisma ORM ומסד נתונים יחסי PostgreSQL. השרת אמון על אכיפת לוגיקה עסקית, חישובי מע"מ, תנאי תשלום שוטף פלוס, מודל הרשאות מבוסס תפקידים (RBAC), אימות דו-שלבי (TOTP / 2FA), יומן ביקורת (Audit Log), הפקת קובצי מס"ב במבנה 128 תווים, וייצוא תנועות יומן מותאמות לחשבשבת.
- **צד לקוח (`web/`):** אפליקציית ווב מתקדמת (PWA - Progressive Web App) מבוססת React 18, TypeScript, Vite ו-SheetJS (XLSX). הממשק מותאם מלא לעבודה בעברית (RTL), ומציג 9 מודולים תפעוליים: סקירת פרויקטים ורווחיות, חשבוניות ספקים, עבודה ועובדים, חוזים ולקוחות, חשבוניות ללקוח, גביית חובות, דוחות חיתוך, ייבוא נתונים וניהול הרשאות.

### עקרונות האבטחה והדיוק הפיננסי
1. **חוק אי-זיוף נתונים פיננסיים בצד לקוח:** כל החישובים של מע"מ (18%), סכום ברוטו, עכבון (Retention), קיזוזים (Offsets), תאריכי ערך וסטטוסי חשבונית מחושבים או נאכפים בצד השרת.
2. **אכיפת תהליך 3-Way Match ושדות חובה:** לא ניתן לאשר חשבונית ספק לתשלום מבלי שסומנה כהותאמה להזמנת רכש ולתעודת משלוח, ומבלי שמולאו שדות החובה שהוגדרו דינמית ע"י מנהל המערכת.
3. **אינטגרציה כפולה מול חשבשבת:** שמירת מפתח חשבון חשבשבת (`hhAccountKey`) לכל ספק, מניעת ייצוא כפול באמצעות סימון אצוות אטומי, ותמיכה בביטול אצווה (Undo).
4. **תזרים מזומנים מבוסס מועדי תשלום 15/30:** שיבוץ אוטומטי של חשבוניות ספקים לשני מועדי התשלום החודשיים הנהוגים במשק הישראלי, עם הפקת קובץ זיכויים במס"ב והתאמת תשלומים מדוחות העברות בנקאיות.

- **3) מנגנונים, אלגוריתמים וספריות:** שימוש בשפת הסכמה של Prisma להגדרת טיפוסי שדות מדויקים, כולל שדות מספריים פיננסיים ברמת דיוק של `db.Decimal(14, 2)` למניעת שגיאות עיגול נקודה צפה.
- **4) קשרי גומלין ואינטגרציות:** מייצר את ספריית `@prisma/client` המשמשת את כלל נתיבי השרת, וממפה ישויות כגון: `User`, `Role`, `Permission`, `Project`, `Supplier`, `SupplierInvoice`, `InvoiceLine`, `Customer`, `Contract`, `BillingDoc`, `Worker`, `Workday`, `AuditLog`, `OrgSetting` ו-`InvoiceFieldSetting`.
- **5) חוקים עסקיים ואבטחה:** אוכף מחיקות משורשרות (Cascade) על שורות חשבונית וימי עבודה, מגדיר מפתחות ייחודיים משולבים (למשל עובד-פרויקט-חודש או תפקיד-תפריט), ומגדיר אינדקסים מהירים ליומן הביקורת.

### 15. `server/prisma/seed.ts`
- **סוג קוד:** TypeScript / Database Seeding Script
- **1) תכלית ואחריות מרכזית:** מבצע אתחול וזריעת נתונים ראשונית במסד הנתונים: תפקידים, מטריצת הרשאות, משתמש מנהל, הגדרות שדות חובה לאישור, הגדרות מס"ב, ספקים ולקוחות אמיתיים, פרויקטים, עובדים ומטריצת ימי עבודה.
- **2) שכבה ארכיטקטונית:** שרת ה-API / שכבת איתחול המסד וניהול מחזור חיי הנתונים.
- **3) מנגנונים, אלגוריתמים וספריות:** מפעיל פעולות `upsert` ו-`createMany` דרך PrismaClient, ומצפין את סיסמת המנהל באמצעות `bcrypt.hash` בעלות מלח 12.
- **4) קשרי גומלין ואינטגרציות:** מייבא את קטלוג החשבונות מ-`real-accounts.ts`, קורא את פרטי המנהל מ-`server/src/env.ts`, ומזין את כל הטבלאות הנדרשות להרצה חלקה של המערכת.
- **5) חוקים עסקיים ואבטחה:** מקבע את מטריצת ברירת המחדל של הרשאות התפקידים (admin, finance, pm, viewer) על פני 9 המודולים, מגדיר שדות חובה לאישור חשבונית (התאמת 3-way match ושיוך שורות לפרויקט), ומבטיח הרצה אידמפוטנטית שאינה דורסת נתונים קיימים.

## חלק 4: תשתית הליבה ונקודות הכניסה של השרת (Server Core Infrastructure & Entrypoints)

### 16. `server/src/app.ts`
- **סוג קוד:** TypeScript / Express Application Factory
- **1) תכלית ואחריות מרכזית:** יוצר ומגדיר את מופע אפליקציית ה-Express, רושם את כלל המידלוורים הגלובליים (אבטחה, לוגים, הגבלת קצב), ומחבר את כל 14 מודולי הנתיבים של ה-API.
- **2) שכבה ארכיטקטונית:** שרת ה-API / שכבת תשתית ה-HTTP וניתוב הבקשות הראשי.
- **3) מנגנונים, אלגוריתמים וספריות:** שילוב ספריות `helmet` להגנת כותרות HTTP, `cors` מבוסס מקורות מורשים, `pinoHttp` לתיעוד בקשות, ו-`express-rate-limit` להגנה ממתקפות Brute-force.
- **4) קשרי גומלין ואינטגרציות:** טוען משתני סביבה מ-`server/src/env.ts`, מחבר את נתיבי המודולים תחת הקידומת `/api/*`, ורושם את פונקציות הטיפול בשגיאות מ-`server/src/middleware/error.ts`.
- **5) חוקים עסקיים ואבטחה:** מגביל קצב בקשות לנתיב `/api/auth` (עד 30 ניסיונות ברבע שעה), מגביל גודל גוף בקשת JSON ל-2MB, ומגדיר `trust proxy` המאפשר עבודה בטוחה מאחורי Reverse Proxy של ספק הענן.

### 17. `server/src/db.ts`
- **סוג קוד:** TypeScript / Database Client Singleton
- **1) תכלית ואחריות מרכזית:** מייצר ומייצא מופע יחיד (Singleton) של `PrismaClient` המנהל את מאגר החיבורים (Connection Pool) של השרת מול מסד הנתונים PostgreSQL.
- **2) שכבה ארכיטקטונית:** שרת ה-API / שכבת הגישה למסד הנתונים (Persistence Infrastructure).
- **3) מנגנונים, אלגוריתמים וספריות:** אתחול לקוח Prisma עם רמות לוג מותאמות דינמית לפי סביבת הריצה (`warn`, `error` בייצור לעומת `query` בפיתוח).
- **4) קשרי גומלין ואינטגרציות:** מיובא ע"י כל בקרי הניתוב, פונקציות ה-middleware של האבטחה, ומנגנון ה-audit לצורך ביצוע שאילתות ומניפולציות בנתונים.
- **5) חוקים עסקיים ואבטחה:** מונע דליפת משאבים והצפת חיבורים למסד הנתונים ע"י שימוש חוזר באותו מופע לאורך כל מחזור החיים של תהליך ה-Node.

### 18. `server/src/env.ts`
- **סוג קוד:** TypeScript / Configuration & Validation
- **1) תכלית ואחריות מרכזית:** טוען, מנתח ובודק את תקינות כל משתני הסביבה הדרושים בעת אתחול השרת, ומבטיח כישלון מיידי (Fail-fast) אם משתנה קריטי חסר.
- **2) שכבה ארכיטקטונית:** שרת ה-API / שכבת תצורה וליבה תשתיתית.
- **3) מנגנונים, אלגוריתמים וספריות:** שימוש בספריית `dotenv` ופונקציית עזר `required()` הזורקת שגיאה ברורה בעת היעדר מפתח סביבה חיוני.
- **4) קשרי גומלין ואינטגרציות:** מזין נתוני תצורה מובנים (פורט, סודות JWT, זמני TTL, כתובות CORS מותרות, פרטי מנהל ראשוני) לקובצי `server.ts`, `app.ts`, `auth.ts` ו-`seed.ts`.
- **5) חוקים עסקיים ואבטחה:** מונע הרצת שרת ללא הגדרת מחרוזת התחברות למסד או מפתחות הצפנה, ומפצל מחרוזות CORS מופרדות בפסיקים למערך דומיינים חוקיים מורשים בלבד.

### 19. `server/src/server.ts`
- **סוג קוד:** TypeScript / Server Bootstrap & Lifecycle Entrypoint
- **1) תכלית ואחריות מרכזית:** מהווה את נקודת הכניסה הראשית (Entrypoint) המפעילה את השרת, פותחת האזנה בפורט המבוקש, ומנהלת תהליך כיבוי מסודר (Graceful Shutdown).
- **2) שכבה ארכיטקטונית:** שרת ה-API / שכבת מחזור החיים של השרת.
- **3) מנגנונים, אלגוריתמים וספריות:** האזנה באמצעות `http.Server` של Node.js, ולכידת אותות מערכת הפעלה (`SIGINT`, `SIGTERM`).
- **4) קשרי גומלין ואינטגרציות:** מפעיל את `createApp()` מ-`app.ts`, עושה שימוש במשתני הסביבה מ-`env.ts`, ומנתק בצורה נקייה את לקוח ה-Prisma מ-`db.ts` בעת כיבוי.
- **5) חוקים עסקיים ואבטחה:** מבטיח כי בעת קבלת פקודת עצירה מענן האחסון, השרת יסיים את הבקשות הפעילות, יסגור את החיבורים למסד הנתונים, ולא ישאיר תנועות תלויות או נעילות פתוחות.

## חלק 5: שכבת ה-Middleware של השרת (Server Middleware Layer)

### 20. `server/src/middleware/auth.ts`
- **סוג קוד:** TypeScript / JWT Authentication Middleware
- **1) תכלית ואחריות מרכזית:** מנהל את מנגנון ההזדהות של המערכת: הפקת טוקני גישה ורענון ב-JWT, אימותם, וחסימת בקשות בלתי מורשות לנתיבים מוגנים.
- **2) שכבה ארכיטקטונית:** שרת ה-API / שכבת מידלוור אימות ואבטחה (Authentication Layer).
- **3) מנגנונים, אלגוריתמים וספריות:** שימוש בספריית `jsonwebtoken` לחתימה ופענוח HMAC SHA-256, והרחבת הטיפוס הגלובלי של `Express.Request` להכללת אובייקט `user` מאומת.
- **4) קשרי גומלין ואינטגרציות:** קורא סודות חתימה מ-`server/src/env.ts` ומעביר את פרטי המשתמש המאומת למידלוור ההרשאות `rbac.ts` ולרושם הביקורת `audit.ts`.
- **5) חוקים עסקיים ואבטחה:** אוכף שימוש בכותרת `Authorization: Bearer <token>`, דוחה טוקנים שפג תוקפם בקוד שגיאה 401, ומפריד בין טוקן גישה קצר-טווח (15 דקות) לטוקן רענון ארוך-טווח (7 ימים).

### 21. `server/src/middleware/error.ts`
- **סוג קוד:** TypeScript / Global Error Handling Middleware
- **1) תכלית ואחריות מרכזית:** תופס ומעבד באופן מרוכז את כלל השגיאות הנזרקות ברחבי השרת, וממיר אותן לתגובות JSON אחידות ומובנות למשתמש ולממשק.
- **2) שכבה ארכיטקטונית:** שרת ה-API / שכבת טיפול בשגיאות וחוסן מערכת (Error Handling).
- **3) מנגנונים, אלגוריתמים וספריות:** זיהוי שגיאות ולידציה של ספריית Zod (`ZodError`), תפיסת שגיאות כפילות ייחודית של Prisma (`P2002`), וטיפול בשגיאות מותאמות אישית עם קודי HTTP ספציפיים.
- **4) קשרי גומלין ואינטגרציות:** נרשם כמידלוור האחרון ב-`server/src/app.ts` ומספק גם מידלוור `notFound` עבור נתיבי API שאינם קיימים (404).
- **5) חוקים עסקיים ואבטחה:** מונע דליפת מחסניות קריאה (Stack traces) לסביבת ייצור, ממיר שגיאות שלמות נתונים של מסד הנתונים לקוד 409 ידידותי, ומחזיר פירוט שדות שגויים בקוד 400 עבור שגיאות ולידציה.

### 22. `server/src/middleware/rbac.ts`
- **סוג קוד:** TypeScript / Role-Based Access Control (RBAC) Middleware
- **1) תכלית ואחריות מרכזית:** אוכף את מודל ההרשאות המבוסס-תפקידים בשרת, ובודק מול מסד הנתונים בכל בקשה ובקשה האם לתפקיד המשתמש יש הרשאת צפייה, כתיבה או מחיקה במודול המבוקש.
- **2) שכבה ארכיטקטונית:** שרת ה-API / שכבת בקרת גישה והרשאות (Authorization Layer).
- **3) מנגנונים, אלגוריתמים וספריות:** פונקציית מסדר-גבוה (Higher-Order Function) המקבלת מפתח תפריט (`menuKey`) ופעולה (`view` / `write` / `delete`), ושולפת שאילתת הרשאה ממוקדת.
- **4) קשרי גומלין ואינטגרציות:** נסמך על המשתמש שחולץ ב-`auth.ts`, מתשאל את טבלאות `Role` ו-`Permission` דרך `server/src/db.ts`, ומגן על כלל הנתיבים במודולים.
- **5) חוקים עסקיים ואבטחה:** מונע לחלוטין מעקף הרשאות מהממשק ע"י בדיקה חיה מול המסד בכל פנייה, וחוסם ניסיונות גישה בלתי מורשים בקוד HTTP 403 Forbidden עם הודעה מפורשת.

## חלק 6: נתיבי ה-API ומודולי השרת (Server API Route Modules)

### 23. `server/src/modules/auth/auth.routes.ts`
- **סוג קוד:** TypeScript / Express Router (Authentication & RBAC)
- **1) תכלית ואחריות מרכזית:** מטפל בכל תהליכי ההזדהות, ניהול משתמשים, אימות דו-שלבי (TOTP / 2FA), והגדרת מטריצת ההרשאות הגלובלית.
- **2) שכבה ארכיטקטונית:** שרת ה-API / מודול הזדהות וניהול משתמשים.
- **3) מנגנונים, אלגוריתמים וספריות:** אימות סיסמאות עם `bcrypt.compare`, בדיקת סיסמאות מורכבות ואימייל באמצעות סכמות Zod, ומחולל קודי TOTP עם `otplib` (כולל הפקת מחרוזות `otpauth://` לקודי QR).
- **4) קשרי גומלין ואינטגרציות:** מעדכן את מודלי `User`, `Role` ו-`Permission`, מנפיק טוקנים דרך `auth.ts`, ורושם אירועי אבטחה ב-`audit.ts`.
- **5) חוקים עסקיים ואבטחה:** חוסם משתמשים שאינם בסטטוס `APPROVED`, מחזיר קוד HTTP 206 כאשר נדרש קוד 2FA, מגן על יצירת/עריכת משתמשים ומטריצת הרשאות תחת הרשאת `permissions:write`, ומבטיח שהודעות שגיאה בכניסה יישארו גנריות למניעת מתקפות ניחוש שמות משתמשים.

### 24. `server/src/modules/billingDocs/billingDocs.routes.ts`

- **4) קשרי גומלין ואינטגרציות:** מתקשר עם טבלאות `BillingDoc`, `BillingOffset`, `Contract`, `Customer` ו-`Project`, ומאפשר המרת חשבון עסקה לחשבונית מס בנתיב ייעודי.
- **5) חוקים עסקיים ואבטחה:** אוכף שעכבון וקיזוזים יחולו אך ורק על חשבוניות מס (ולא על חשבונות עסקה), מחשב את היתרה הפתוחה בזמן אמת, ודורש הרשאות `docs:view`, `docs:write` ו-`docs:delete` בהתאמה לפעולה.

### 25. `server/src/modules/collections/collections.routes.ts`

- **1) תכלית ואחריות מרכזית:** מפיק דוח גיול חובות לקוחות מפורט, ומאפשר תיעוד פעולות גבייה שוטפות (שיחות טלפון, מכתבי התראה, תזכורות במייל) מול חשבוניות פתוחות.
- **2) שכבה ארכיטקטונית:** שרת ה-API / מודול גבייה וניהול לקוחות חייבים.
- **3) מנגנונים, אלגוריתמים וספריות:** אלגוריתם פילוח חובות לפי סבבי גיול ימי פיגור (טרם הגיע, 1–30, 31–60, 61–90, ומעל 90 יום) בהתבסס על הפרשי ימים ב-UTC.
- **4) קשרי גומלין ואינטגרציות:** שואב חשבוניות פתוחות מ-`BillingDoc` (למעט חשבונות עסקה), שומר רשומות מעקב ב-`CollectionAction`, וקושר את הפעולה למזהה המשתמש המבצע.
- **5) חוקים עסקיים ואבטחה:** מסנן אוטומטית חשבוניות ששולמו במלואן, מחשב ימי פיגור מדויקים מול תאריך היעד, ומחייב הרשאת `collections:write` לתיעוד פעולות גבייה ומעקב עתידי (`nextFollowup`).

### 26. `server/src/modules/contracts/contracts.routes.ts`

- **1) תכלית ואחריות מרכזית:** מנהל את קטלוג הלקוחות וחוזי הפרויקטים, ומספק תמונת מצב מצטברת של ביצוע כספי מול החוזה (סך חויב, סך נגבה, עכבונות המוחזקים אצל הלקוח ויתרות פתוחות).
- **2) שכבה ארכיטקטונית:** שרת ה-API / מודול חוזים, לקוחות ומעקב הכנסות פרויקטליות.

## המלצות והנחיות להמשך פיתוח אוטומציית החשבוניות

לקראת הטמעת מודול אוטומציית החשבוניות וחיבורו המלא להנהלת החשבונות של אתניב, להלן דגשים ארכיטקטוניים מנחים המבוססים על הביקורת שבוצעה:

1. **שימור מודל ה-3-Way Match:** כל מנגנון אוטומטי של פענוח חשבוניות (OCR / AI) חייב להזין ישירות את השדות `purchaseOrderNo`, `deliveryNoteNo` ולסמן את דגל `matched`, תוך עמידה בהגדרות שדות החובה ב-`InvoiceFieldSetting`.
2. **אימות מפתח חשבון בחשבשבת לפני קליטה:** בעת זיהוי ספק חדש, יש לוודא צימוד מיידי של `hhAccountKey` מתוך 756 הספקים הקיימים ב-`real-accounts.ts`, כדי למנוע חסימת ייצוא של אצוות שלמות ב-`hashavshevet.routes.ts`.
3. **הפרדת מע"מ תשומות (Input VAT) ומספר הקצאה:** בהתאם לחוק החשבוניות ומודל הקצאת מספרי החשבוניות של רשות המסים בישראל, מומלץ להוסיף לשכבת הנתונים של `SupplierInvoice` שדה ייעודי עבור "מספר הקצאה" (Allocation Number) לחשבוניות מעל הרף החוקי.
4. **עבודה בארכיטקטורת Staging:** יש להמשיך להשתמש בטבלאות התיווך של המערכת כ-Staging מאובטח, שבו חשבוניות נקלטות, מאושרות ע"י גורם מוסמך, ורק אז מיוצאות לחשבשבת ולאצוות מס"ב עם חותמת מועד ואצווה למניעת כפילויות.
