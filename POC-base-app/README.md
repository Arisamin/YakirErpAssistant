# מערכת ניהול פרויקטלי-פיננסי — <CompLTDNamePlaceHolder>

אפליקציית ווב מאובטחת (PWA) לניהול פרויקטלי: הוצאות ספקים, לקוחות וחוזים,
עלויות עבודה, גביית חובות, ורווחיות — עם אינטגרציה לחשבשבת.

## מבנה המאגר (Monorepo)

```
POC-base-app/
├── server/    # שרת API — Node.js + TypeScript + Express + Prisma + PostgreSQL  ✅ שלב 1
└── web/       # אפליקציית PWA — React + TypeScript + Vite                        ✅ שלב 2
```

## פריסה לייצור

ראה `DEPLOY.md` (מדריך מעשי תמציתי) ואת `render.yaml` (Blueprint לפריסה ב-Render — שרת + PWA + מסד).
קבצי סביבה לדוגמה: `server/.env.production.example`, `web/.env.production.example`. יצירת סודות: `scripts/gen-secrets.sh`.

## הרצה מהירה (מקומית)

1. הרץ את השרת: ראה `server/README.md` (התקנה, מיגרציה, זריעה, `npm run dev`).
2. הרץ את ה-PWA: ראה `web/README.md` (`npm install`, `npm run dev`).
3. פתח `http://localhost:5173` והתחבר עם המשתמש שנוצר בזריעה.

- **שלב 4 (הושלם)** — מודול חוזים ולקוחות: API לחוזים (עם חישובי חויב/נגבה/עכבון/יתרה מתוך מסמכי החיוב) ומסך מלא ב-PWA.

- **שלב 7 (הושלם)** — סקירת פרויקטים ברווחיות אמיתית: נתיב שרת שמצליב הכנסות (חשבוניות לקוח), חומרים (חשבוניות ספק) ועבודה מול תקציב, ומסך סקירה מלא ב-PWA. כולל חשבוניות ספק לדוגמה בזריעה.

### עדכונים
- מודול חשבוניות ספקים (לשעבר "הוצאות ספקים"): נוספה התאמה להזמנת רכש ולתעודת משלוח (3-way match) — שדות מספר הזמנת רכש ותעודת משלוח, סימון "הותאם", ועמודת התאמה ברשימה.
- אכיפת תהליך: לא ניתן לאשר חשבונית לתשלום ("מאושר לתשלום") לפני שסומנה כ"הותאמה" — נאכף בשרת ובממשק. נוסף גם שדה "הערות" במלל חופשי לחשבונית.
- חשבונית עצמית: נוסף שדה "מספר חשבונית עצמית" לספקים המחייבים הפקת חשבונית עצמית.
- שדות חובה גמישים לאישור: מנהל המערכת מגדיר במסך "ניהול הרשאות" אילו שדות (התאמה, סיווג לפרויקט, הזמנת רכש, תעודת משלוח, חשבונית עצמית, הערות) הם חובה לאישור חשבונית לתשלום. הכפייה נאכפת בשרת ובממשק — לכל מאשר, בהווה ובעתיד. שדות החובה מסומנים ב-* בטופס.
- תאריכים נוספים: נוסף "תאריך קליטת החשבונית" ו"תאריך תשלום בפועל" (במקבץ אישור וסטטוס).
- פורמט תאריך: כל התאריכים בתצוגה ובדוחות/ייצוא מוצגים כ-DD/MM/YYYY.
- תזרים מזומנים חדש: לוח תשלומים לספקים לפי שני מועדי תשלום חודשיים (15 ו-30) — כל חשבונית משויכת למועד הקרוב שחל בתאריך הפירעון או אחריו. התשלומים ממוינים לפי מועד תשלום ואז לפי שם ספק (א-ב) ואז לפי מועד פירעון. התזרים כולל יתרת פתיחה, תחזית תקבולים מול תשלומים, ויתרה מצטברת. ניתן לייצוא ל-Excel/Word/PDF.
- מקבץ תשלומים (מס"ב): הפקת קובץ מס"ב לספקים לפי טווח מועדי תשלום שנבחר — כולל רק חשבוניות מאושרות לתשלום שטרם שולמו. **הערה:** פרטי הבנק וקוד המוסד שנזרעים הם נתוני דוגמה (Placeholder); יש להזין נתונים אמיתיים ולאמת את מבנה הקובץ מול מפרט המס"ב של הבנק לפני שימוש בייצור.
- ניהול ספקים ופרטי בנק: במסך חשבוניות ספקים נוסף "ניהול ספקים ופרטי בנק" — עריכת ח.פ, קוד בנק, סניף ומספר חשבון לכל ספק (נתיב PUT /suppliers/:id).
- הגדרות מס"ב ברמת ארגון: במסך ניהול ההרשאות נוסף סעיף "מוסד שולח" — קוד מוסד שולח, שם המוסד ויתרת פתיחה לתזרים (נתיב GET/PUT /org-settings, עדכון למנהל בלבד).
- מבנה רשומות מס"ב: פאנל המס"ב מציג את מבנה הרשומות המלא (סוגי רשומה 1/2/5, מיקומי שדות, אורכים ודוגמאות) ואת קוד המוסד השולח בפועל.
- ייצוא לחשבשבת: הפקת קובץ אקסל לייבוא תנועות לחשבשבת במבנה התבנית (גיליון "חשבוניות ספקים": ספק | תאריך אסמכתא | אסמכתא | פרויקט | פרטים | חובה | תאריך ערך), שורה לכל שיוך פרויקט, סכום לפני מע"מ, ועמודת "ספק" = מפתח חשבון בחשבשבת. "תאריך אסמכתא" = תאריך החשבונית; "תאריך ערך" = מועד התשלום לפי תנאי התשלום של הספק. נוסף שדה "מספר ספק (חשבשבת)" ותנאי תשלום ניתנים לעריכה לכל ספק ב"ניהול ספקים" — נמשכים אוטומטית בעת קליטת חשבונית (עם אפשרות לשינוי ידני).
- מניעת ייצוא כפול: כל חשבונית שיוצאה מסומנת (hhExportedAt + אצווה), וההפקה כוללת רק חשבוניות מאושרות שטרם יוצאו — כך שאותה חשבונית לא תיקלט פעמיים. יש היסטוריית אצוות עם אפשרות ביטול אצווה, וחיווי "H" (יוצא לחשבשבת) ברשימת החשבוניות. הסימון והבחירה אטומיים בשרת (POST /hashavshevet/export).
- מע"מ משתנה לפי ספק: לכל ספק שדה "מע"מ %" (ברירת מחדל 18%, 0% לספק פטור כגון אילת), ניתן לעריכה ב"ניהול ספקים". בקליטת חשבונית שיעור המע"מ נמשך אוטומטית מהספק ומחושב לסכום; ניתן לשינוי ידני לחשבונית בודדת. הסכום לתשלום (total) כולל מע"מ, ובתזרים מופיע במועד ה"תאריך ערך" של החשבונית.
- רשימות אינדקס: הזריעה כוללת את רשימות הספקים והלקוחות מדוח אינדקס החשבונות בחשבשבת (server/prisma/real-accounts.ts — 756 ספקים, 172 לקוחות, עם מפתח חשבון וע.מ). נתוני הדוגמה הישנים הוסרו; הזריעה מתחילה נקייה מתנועות (ללא חשבוניות/חוזים לדוגמה) — הנתונים הפיננסיים ייקלטו ע"י המשתמש. ניהול הספקים כולל חיפוש (עקב היקף הרשימה).
- תזרים כרונולוגי (יומן תנועות): דוח התזרים נבנה מחדש כיומן כרונולוגי של כל תנועות ההוצאה וההכנסה — שורה לכל תנועה, ממוינת לפי תאריך, עם יתרת פתיחה, סכומי הוצאה/הכנסה ויתרה מצטברת רצה (נתיב GET /reports/cashflow מחזיר `{opening, ledger, totals}`). כל שורה כוללת תאריך בפועל, תאריך ערך, סעיף (ספקים/לקוחות), שם, אסמכתא, תיאור, פרויקט וסטטוס (צפוי / שולם / התקבל / חשבון עסקה). ניתן לייצוא ל-Excel/Word/PDF.
- עדכון תשלומים ממקבץ (PDF): תשלומים לספקים מבוצעים במקבץ בבנק. נוסף ממשק "עדכון תשלומים ממקבץ" בדוח התזרים — העלאת קובץ ה-PDF של ההעברות, הזנת מועד ההעברה בפועל, וסימון החשבוניות ששולמו (סימון מונחה: הדבקת מספרי החשבוניות מדוח ההעברות מסמנת אוטומטית את המתאימות). הסימון מעדכן את החשבוניות כ"שולמו" עם תאריך ואסמכתת מקבץ, והתזרים מתעדכן בהתאם (נתיבי GET /payments/open ו-POST /payments/mark-paid). נבחרה גישת סימון מונחה כיוון שטקסט ה-PDF מקודד בגופן ולא ניתן לפענוח אוטומטי אמין.
- חשבון עסקה (פרופורמה) והמרה לחשבונית: חשבוניות ספק וחשבוניות לקוח יכולות להיקלט כ"חשבון עסקה" (פרופורמה). בטופס קליטת חשבונית ספק נוסף בורר "סוג מסמך" (חשבונית מס / חשבון עסקה — שדה docKind). חשבון עסקה מוצג בתזרים כתנועה צפויה בלבד ואינו נכלל בייצוא לחשבשבת/מקבץ; מדוח התזרים ניתן להמיר אותו לחשבונית מס בלחיצה, והתנועה מתעדכנת (נתיבי POST /supplier-invoices/:id/to-invoice ו-POST /billing-docs/:id/to-invoice).
- ניהול ומחיקה של נתוני יסוד: נוספו יכולות עריכה ומחיקה מלאות לפרויקטים, ספקים, לקוחות ועובדים (בנוסף למחיקת חשבוניות וחוזים שכבר היו). "ניהול פרויקטים" (בסקירת פרויקטים) ו"ניהול לקוחות" (בחוזים) — הוספה/עריכה/מחיקה; מחיקת ספק (במסך "ניהול ספקים") ומחיקת עובד (במסך "עבודה ועובדים"). כל מחיקה מאובטחת בהרשאת "מחיקה" ומאושרת ע"י המשתמש. הגנת שלמות נתונים: השרת חוסם מחיקת פרויקט המקושר לחשבוניות/חוזים/ימי עבודה, מחיקת ספק המקושר לחשבוניות, ומחיקת לקוח המקושר לחוזים — עם הודעה ברורה (409). מחיקת עובד מסירה גם את רשומות ימי העבודה שלו. כך ניתן לנקות את נתוני הדוגמה (פרויקטים/עובדים) ישירות מהממשק לקראת המעבר לייצור.
