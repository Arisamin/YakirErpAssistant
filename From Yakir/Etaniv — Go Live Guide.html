Before you start — accounts & files

~10 min
  • Unzip etaniv-app.zip (the file I sent you) into a folder on your computer — remember where it is.
  • Create a free GitHub account at github.com (this is where the code lives — private).
  • Create a Render account at render.com — choose “Sign up with GitHub” so they connect easily.
  • Have a credit card ready (for the paid server + database) and access to where you manage the etaniv.co.il domain (optional, for custom addresses).
1

Put the code on GitHub (no commands — using GitHub Desktop)

~10 min
  • Download GitHub Desktop from desktop.github.com, install it, and sign in with your GitHub account.
  • In GitHub Desktop: File → New repository. Name it etaniv-app, pick any location, click Create repository.
  • Open that new etaniv-app folder on your computer and copy all the unzipped files into it (the server, web folders, render.yaml, etc.).
  • Back in GitHub Desktop you'll see all the files listed. At the bottom-left type a message like Etaniv system v1 and click Commit to main.
  • Click Publish repository. ✔ Keep the box “Keep this code private” checked. Publish.
Tip: this GitHub step is the only slightly technical part. If you have a tech-savvy friend, this is the one place they could save you 10 minutes. Everything after is clicking in Render.
2

Deploy on Render (it reads the blueprint and builds everything)

~10 min + build
  • Log in to dashboard.render.com. Click New + → Blueprint.
  • Connect GitHub and give Render access to your etaniv-app repository (you can limit it to just that repo). Select it.
  • Render finds render.yaml and shows 3 things it will create: etaniv-db (database), etaniv-api (server), etaniv-web (the app).
  • It will ask you to enter ADMIN_PASSWORD. Type a strong temporary password and write it down — it's your first manager login (you'll change it in Step 6).
  • Click Apply / Create. Add your card if prompted. The first build takes about 5–10 minutes — wait until etaniv-api shows Live.
Already handled for you: the security keys (JWT secrets) are generated automatically, the database tables are created automatically on first start, and the server is set to a paid plan so it never “sleeps.”
3

Upgrade the database to a paid plan — do it the same day

~3 min
  • In the Render dashboard open etaniv-db → look for Plan (or Settings).
  • Change it from Free to a paid plan (the Basic ~$7/month tier is plenty to start). This keeps your data and turns on automatic daily backups.
Important: a free database on Render expires 30 days after it's created (then a 14-day grace period). For real financial data you don't want that risk — upgrade now, on day one, and you're safe with backups.
4

Load your real data (one-time)

~3 min
  • Open etaniv-api → the Shell tab (a black command box inside Render).
  • Type this and press Enter:
    $ node dist/prisma/seed.js
  • Wait for “הזריעה הושלמה בהצלחה”. This loads roles & permissions, your 756 suppliers + 172 customers, and your manager account.
  • Later, inside the app, delete the 3 sample projects (101/102/103) and 5 sample workers (as we discussed) so the system is fully clean of demo data.
5

Your web addresses (test now, custom domain optional)

~10 min
  • Test immediately: Render gives each service a free address like etaniv-web.onrender.com — open it to check the system works before touching your domain.
  • For your own addresses (recommended): in etaniv-api → Settings → Custom Domains add api.etaniv.co.il; in etaniv-web add app.etaniv.co.il.
  • Render shows a DNS record (a CNAME) for each — add those two records where you manage etaniv.co.il DNS. HTTPS/SSL is then issued automatically.
Good to know: the blueprint already expects exactly app.etaniv.co.il and api.etaniv.co.il, so if you use those names, no extra settings are needed. If you pick different names, tell me and I'll adjust two values (CORS_ORIGINS and VITE_API_URL).
6

First login & lock it down (most important step)

~5 min
  • Open your app address and log in with yakir@etaniv.co.il + the temporary password from Step 2.
  • Change your password right away to a strong, private one.
  • Turn on Two-Step Verification (2FA): scan the QR code with Google Authenticator or Microsoft Authenticator, then enter the 6-digit code to confirm.
  • Add your other users in the Permissions screen and assign each a role — every user can (and should) enable their own 2FA.
